# SEQ Elevate Platform — Build Log

A chronological log of every meaningful step and decision in building the SEQ Elevate platform. Purpose: full transparency, and the ability to retrace how any part was built so future work (new courses, new projects, new features) can follow the same patterns.

**How to read this**: newest entries at the bottom of each phase. Each entry is dated and tagged. Decisions that change direction are also cross-referenced in `DECISIONS.md`. Component-level documentation lives in `STORYBOOK.md` and the in-app gallery.

Legend: `[BUILD]` code/feature · `[DECISION]` a choice made · `[INFRA]` infrastructure/tooling · `[DOC]` documentation · `[FIX]` correction · `[BLOCK]` waiting on external input

- `[BUILD]` `c9a1713` (D37, D69, D79, D80) **One server action adds a browser's guest work to the account, part by part, in one transaction** (`claimGuestWork` in `src/app/actions/learner.ts`; what each answer means is in `src/lib/guest-claim.ts`).
  - **The course** moves only into an account with no progress in it, through the save's own transaction (`progressInTx`, taken out of `saveProgress`: the completion, the kill switch's rule for it and its badge). An account with progress in it gets nothing: "already" when it holds all of the guest's, "kept" otherwise. A course nobody can open any more is "unavailable".
  - **The Comp Card** moves only into no card, or a blank one (no answer, the confidence untouched) that isn't shared, and is written as "Only me". The same card is "already" there; a card with something of the account's own is "kept"; a blank shared one gets nothing ("shared"): adding never shares.
  - **Badges** are a union, each given as the award action gives it (`badgeMayBeGiven`, now the award's own check too).
  - **Locks**, in this order: the User row (KEY SHARE); the Course row (KEY SHARE, or UPDATE when the completion may make its badge); the enrolment, then the Comp Card, each inserted unless there, then locked, read and decided as read; the badges, inserted unless there.
  - **Nothing is written** for another account's session, an incomplete profile, a claim that isn't one, a text too long to add (a Comp Card answer over 2,000 characters, a reflection answer over 5,000: named in the answer) or a claim bigger than one save. Each claim's outcome is logged as counts per part, without the learner, the course or a text.
